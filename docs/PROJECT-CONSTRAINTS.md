# 项目协作与发布约束（强制）

本文件是《掀起你的头盖骨》持续开发、验收和发布的最高执行约束。自 2026-11-18 起，用户明确指定：**所有修改只能直接基于 `main` 分支，禁止创建任何新分支。** 本文件优先于所有旧计划、历史报告、自动化提示和旧分支记录。

## 1. 唯一源码分支：main（绝对强制）

- **唯一可写源码分支是 `main`。** 所有游戏代码、美术资源、测试、文档、QA、脚本、依赖配置和工作流修改，均直接以远端最新 `main` 为父历史并提交到 `main`。
- **禁止创建任何新分支**，包括但不限于 `iteration-latest`、`iteration-*`、`iteration-v*`、`release-*`、`prestudy/*`、`agent/*`、临时集成分支、候选分支、备份分支或个人分支。不得为了 PR、CI 候选、临时修复或并行工作创建分支。
- 不使用分支/PR 合并流程。所有获准修改直接在 `main` 上进行；候选验证是对 `main` 当前提交执行的验证阶段，不对应另一条分支。
- `gh-pages` 仅是 GitHub Pages 正式部署产物分支，只能由正式部署工作流更新；不得在其上开发源码、测试或手工编辑，也不得将它当作第二条源码分支。
- 现存的非 `main`、非 `gh-pages` 分支一律视为只读历史引用，不得向其写入、不得将其设为开发基线。历史成果需要恢复时，只能对照最新 `main` 做文件/函数级差量审查，再直接提交到 `main`；不得整树覆盖或盲目合并。
- 本规则禁止创建新分支，不等于授权盲目删除历史分支。清理历史引用前必须确认其独有提交已进入 `main` 或已存在经验证、不可变且可恢复的归档；不得丢弃独有工作。不得删除 `gh-pages`。
- 每次写入前 fresh-read 远端 `main` HEAD、目标文件 blob SHA 和工作流状态。更新 `main` 必须使用最新 expected SHA、fast-forward（`force=false`）；若 HEAD 变化、lease 冲突或有并发提交，立即停止并重新读取，不覆盖、不强推、不抢占。
- 同一时间只允许一个写入者修改 `main` 并推进发布闭环。其他会话/自动化只能读取或等待，不得另建分支并行写入。
- 如果仓库保护规则或当前工具拒绝直接写入 `main`，必须如实报告阻塞并等待用户处理权限/保护设置；**不得通过创建分支、PR、强推或其他方式绕过本规则。**

## 2. 基于 main 的安全整合方式

- 每轮先读取最新 `main`、README、项目约束、角色美术约束、当前迭代记录、QA、Actions 和现有部署状态；不得使用记忆中的旧 SHA 作为当前基线。
- 本地源码包或历史提交只能作为差量来源。逐路径核对文件名、blob SHA、文件大小、文件模式、调用关系和依赖；先识别 main 上已有的等价改动，避免重复修复。
- 当完整游戏 `dist/` 通过清单核对时，可以将其作为单一候选内容直接更新到 `main`：先比较路径清单、SHA、大小和模式，确认没有删除 main 仍需要的运行文件，所有新增路径均纳入，并保留 CNAME、空 `.nojekyll`、首页/模块版本戳。
- 整体替换仅限经过审查的 `dist/` 及配套运行资源/版本文件。不得整树覆盖 `.github/`、`scripts/`、`tests/`、`docs/`、package/锁文件、QA证据或工作流；这些内容必须基于最新 main 做精确文件/函数差量。
- 旧分支或旧候选中的独有内容，只能以经过审查的差量形式直接吸收到 main；不得将旧分支合并为 main 的替代基线，不得创建恢复分支。
- 保留六章、十节日、旧游戏、碰撞物理、输入、存档/奖励/选择、ARIA/语义、企业页脚和全部精确网络失败预算。测试失败原样保留并因果修复，不 skip、不放宽阈值。

## 3. 每批更新的 main-only 强制闭环

1. **读取基线**：fresh-read `main` SHA、工作区/远端差异、当前 Actions 与 Pages 状态；确认没有其他写入者正在修改 main。
2. **直接修改 main**：所有实际代码、美术、测试和必要文档变更都以该 main SHA 为父提交写入 main；更新本轮 QA/交接记录。禁止创建分支或 PR。
3. **执行 main 候选验收**：对该 main 提交运行完整 Node 测试、资源/版本引用检查、真实 Chromium 1280/390/320 视口和输入，以及故障资源/迟到、暂停/减动、剧情逐页 decode、物理/碰撞/解锁/存档/奖励/网络账本门槛。
4. **失败即停**：候选未通过、浏览器证据不足、artifact 无法独立审计或出现并发冲突时，不更新 Pages、不覆盖稳定部署；保留原始失败并记录具体原因。修复仍只能直接提交 main，再重新执行完整验收。
5. **同一轮立即部署**：main 候选验收成功后，基于该精确 main SHA 生成 Pages 运行树并运行正式部署工作流，更新 `gh-pages`；不得推迟到下一轮或累积多轮更新。部署失败时保留旧站点并如实报告。
6. **部署后立即验证**：运行新的 main 完整 HTTPS 工作流，访问正式 `https://tougaigu.com/`；下载本轮源代码、Pages/live 官方 artifacts，逐路径核对 path/blob SHA/size/mode 与目标 dist。核验唯一空 `.nojekyll`、单行 `CNAME=tougaigu.com`、首页目标版本、关键 JS/CSS/图片 HTTP 响应及正式域名实际返回的版本。
7. **如实报告**：只有本轮 main 候选、Pages run、main HTTPS run、artifact 独立审计、线上版本和关键资源响应全部成功，才报告“已上线”。否则明确区分“main 候选未通过”“main 已更新但未部署”“Pages 部署完成但 main HTTPS 未通过”，列出 main SHA、Pages run、HTTPS run、线上版本和缺口。

## 4. 自动化入口（main only）

- `iteration-check.yml` 的 push 触发只允许 `main`；`workflow_dispatch` 也必须检查并拒绝任何非 `refs/heads/main` 的运行。
- 不再存在候选分支 CI、候选分支公网跳过逻辑或 PR 合并门槛；所有候选与正式公网验证均由 main 对应提交执行。
- 所有 game verification runs 使用同一个仓库级 concurrency group，`cancel-in-progress: false`，避免多个 main 验证/部署互相争用。
- Pages 发布只允许基于已通过完整 main 候选验收的 main SHA 执行；禁止从任何历史分支直接发布。

## 5. 视觉基准

唯一角色/场景视觉依据为用户批准的原始设定板 `docs/art-reference/approved-board.png`，必须核验其 SHA-256 为 `f728aa967f5ccd0fcb8a3ea2a13015f88e1904a293a77626a7770798a4891793`。阿拾为棕色短发、蓝夹克、米色内搭、旅行背包；拾光为长发、红围巾、米色外衣的人形女孩。头盖骨仅为“打开脑洞”的比喻，不得制作字面头骨头盔。不得以旧银发/湖绿围巾/小光灵方案替代批准基准。

## 6. 主角实景角色与自动迭代美术约束（强制）

完整、可执行的角色与游戏实景美术规则见 [`docs/CHARACTER-ART-CONSTRAINTS.md`](CHARACTER-ART-CONSTRAINTS.md)，该文件与本文件同为强制项目约束。所有自动迭代必须读取并执行，不得只在某次对话中临时遵守。

- 阿拾身份固定：棕色短发、自然人脸、蓝色夹克、米色内搭、旅行背包。
- 拾光身份固定：长发、红围巾、米色外衣、完整的人形女孩；严禁回退为小光灵、光球或非人形发光体。
- 唯一视觉基准是用户批准的原始 1536×1024 设定板；使用前核对 `docs/art-reference/approved-board.png` 存在且 SHA-256 精确等于 `f728aa967f5ccd0fcb8a3ea2a13015f88e1904a293a77626a7770798a4891793`。不得用重绘概念图替代。
- 角色改进必须进入真实游戏 Canvas 实景：五官、头发、人体比例、服装、背包/围巾、动作、遮挡、光影和材质。头像、档案肖像、SVG、独立模拟画板仅能作为配套，不得代替实景重绘。
- 后续每轮自动迭代把角色细腻度、美观度、自然比例、动作连贯度和场景光影协调列为核心优先级；优先于单纯版本号、重复审计脚本、无实景效果的表面更新。
- 每轮必须以真实 Chromium 的 1280/390/320 视口检查 Canvas 角色，覆盖站立/移动/跳跃或落地/互动姿态；与上一稳定版本同场景同动作对照，确认提升真实可见。模拟触摸不得冒充实体手机/Safari/GPU 验收。
- 96px 裁切合成、局部形变补间、低分辨率放大或重采样资源不得标称高清精绘/逐帧动画。真实资源来源、尺寸和限制必须如实记录。
- 角色身份特征缺失、游戏实景未改变、质量没有明确提升、main 浏览器验收失败或证据不足时，本轮角色优化不通过；不得部署。
- 不得为美术改动放宽物理、碰撞、输入、存档/奖励、剧情解锁、暂停/减少动态、ARIA/语义或精确网络账本门槛。
