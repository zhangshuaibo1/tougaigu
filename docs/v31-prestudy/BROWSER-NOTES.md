桌面收票后原本会耗能，票的成功事件早已到期，因此桌面收票阶段只要求自由灵魂笑脸；不要求桌面在这张票归位后仍笑。第二盏灯原来有 1500 ms 等待，也没有加入合盖笑脸门槛。

**本路线不证明闭盖疲倦。** 阿拾的疲倦阈值是 `<20`，拾光的半闭眼阈值是 `<25`，两者不能混用。这里的 `<20` 身体画面仍是 `form=soul / capPhase=open`。原 E 一按下身体就开始恢复能量；要在完整合盖后仍低于 20，需要更深一次耗能，这不在这项增量范围内。离线预研已有的“闭盖疲倦”图片仍保留其离线证据属性。

## 读取的是实际哪一帧

`browser-smoke.py` 原有的内存追加模块探针仍是唯一的运行时入口。它以和产品渲染相同的 `reducedMotion ? 0 : visualTime` 读取一次 `getCharacterPresentation(t)`，把该结果传给一次 `getSoulPresentation(character)`，再将真实身体、真实呈现的灵魂、同一个时刻传给生产导出的 `getTravelerFaceView` 与 `hasSoulJoy`。这些方法都是只读的，没有再次更新动画或物理。

额外事实只有事件剩余时间、实际记忆/谜灯布尔状态、呈现灵魂、原始灵魂、归位起点和头盖进入进度。独立验收同时检查实际能量、事件剩余时间、主线范围、原眨眼和注视方向。归位位置用真实 `openingWorld` 与实际 `returnFrom/age` 核对原曲线，不能拿仍存放在 `game.soul` 的旧坐标替代返回中的角色。

观察器在输入之前装好，以 RAF 读取现有帧。目标第一次出现时锁存快照，必要时从 `#dream-canvas` 导出当时的原始 PNG；不调用 `render()`，不裁剪、缩放、合成或重画角色。现有页面截图也继续保留。捕获端只记录与当前阶段相关的 E、掀盖按钮和继续按钮原生事件，不取消事件、不改变焦点、不注入点击。

观察数据有明确上限：最近 96 个快照、32 条相关输入、8 条最早连续性错误；图片按目标状态每项只导出一次。收票、首灯、耗能观察器分别最多存活 16、5、27 秒，最后一个上限包含原 HUD 尺寸检查和归位阶段；**它不是把耗能门槛从 21 秒放宽到 27 秒**。耗能 `<20` 锁存还要独立满足原 21 秒截止时间。

原事件的剩余时间在相邻样本间只能按实际游戏时间递减。只有亲眼观察到这张票或第一盏灯的真实状态变化才允许原事件赋值；其余刷新、第二次收集、另一次点灯、换身体、换运行、死亡、倒退时钟都使该阶段失败。长耗能期间被滚动移出数组的帧仍在观察时执行这些连续性检查，首次事件和关键姿态另外锁存。

## 即时证据与失败处理

每个已完成阶段立即写 JSON 和已经捕获的原 Canvas PNG，不等六章路线走完才保存。例如：

- `1280-face-ticket-collected.json`：桌面第一张票，完成后立即清理该观察器。
- `390-face-ticket-collected.json`、`390-face-ticket-returned.json`：手机收票与随后真实归位；320 有对应文件。
- `1280-face-fatigue-soul-low-energy.json`、`body-tired-open.json`、`phone-low-energy.json`、`returned.json`：共同截止时间内的两级疲倦、原手机 HUD 尺寸和恢复。
- `1280-first-lamp-face-lamp-returned.json`：正常首灯继续点击、E、归位与合盖笑脸。
- `390-face-festival-exclusion.json`、`320-face-festival-exclusion.json`：原有万圣节访问中的范围排除。

JSON 保留输入捕获时的实际快照、每个锁存的序号/时刻/尺寸、连续性错误、原 Canvas 的文件名和尺寸。输入捕获不是“所有事件处理器都已完成”的声明；实际返回/闭盖仍由后续 RAF 状态单独验证。中途检查失败、原移动失败或 Python 异常都会进入清理：停止 RAF、取消观察超时、移除捕获监听器、删除临时观察器，并先落下部分 JSON，再尝试失败页面截图。截图传输失败会另行记入证据，同时保留原始失败。

## 当前已验证与尚未验证

本地目标测试：新浏览器表情验收 **6/6**；旧浏览器旅行者验收的机械适配 **4/4**。两组都直接枚举运行，另做 Python 语法检查和 `git diff --check`。没有重跑全套，也没有在本地启动浏览器。

新增测试用真实引擎和正常输入方法生成离线状态，再把实际生产 helper 和原文探针放进 VM。它检查六章正例、十个节日范围排除、实际收票/首灯/归位/自然耗能快照，以及过期或刷新的笑脸、旧身体、错误返回坐标、重复或非真实输入记录、23 与 20 的混淆、超时、错误手机尺寸、丢失阶段、虚构闭盖疲倦等具体坏证据。另有共同截止时间、有限记录/监听器清理、原错误加截图传输失败的回归。

这些测试中的事件对象、RAF 调度和 Canvas 导出接口是离线夹具；它们验证验收器拒绝什么，不能证明浏览器产生了真实触点或精致画面。测试数据通过临时 JSON 文件传入 Python 并设 30 秒子进程上限，避免夹具标准输入等待阻塞。

下一项必要工作仍是由正式 GitHub Actions 在同一完整路线实际执行这些新增门槛，保留每个阶段的 JSON/PNG，并在末尾通过原精确网络与错误核账。390/320 仍是 Chromium 触摸模拟；实体手机、Safari、真实 GPU 和长期设备性能未验证。本文件不会把这段本地增量标为已上线。
