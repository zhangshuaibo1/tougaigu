# v34 只读视觉预研：给抬起的盖子留出画面边距

**状态：证据与设计预备完成；没有修改或发布 v34，也没有修改冻结的 v31 / v32 / v33 工作树。** 全部输出仅在本 `/tmp/tougaigu-v34-phone-cap-study` 目录。下面的 proposal 图是原 Canvas 绘制器的离线投影比较，不是浏览器、实体设备、新正式版本或完整剧情验证。

## 推荐的唯一切片

做「窄屏近身抬盖留边」：当身体与拾光本来仍能同框时，让整套角色、握盖手、盖上服饰和世界场景使用一致的、有少量边距的相机投影。保留原骨架、原开合角度、原世界坐标和原可踩面。

这能改善一个已有、可见的问题：主角的脸仍在画面里，伸起的骨盖和帽尖却被左边缘切掉。它比单独缩帽子可靠，因为现有 390 画面的骨盖本体也可能出界。它不意味着身体始终留在画面里：拾光远行和现有活动专用构图继续优先。

## 原骨架与相机的事实

`createCapRig()` 已经正确地把身体、头部、盖与握点串在一起：

- 盖围绕固定铰链 `(-22,-13)` 转动，帽饰在同一个 `capLocalMatrix` 内。
- 左手追踪 `CAP_GRIP=(-13,-13)` 的真实矩阵结果；该记录的腕 / 握点距离约 `5.684e-14` 世界单位，属于浮点残差，不能写成测得绝对零。
- 拾光出入与牵引线共用 `openingWorld`；脚和阴影继续使用世界平台投影。
- 普通相机目标是当前操控对象的 x 减去 `0.43 × viewWidth`，平时用原 `dt × 5.5` 跟随；减少动态使用原立即落定语义。
- resize 时 `updateViewport()` 主要裁限既有 camera；普通 update 才继续追随新尺寸下的目标。活动构图另有优先规则。

## 单一方案的边界与接入要求

### 近身同框的条件

仅主线的窄屏普通构图参与；关闭 / 销毁 / 非有限上下文、桌面和活动专用构图立即走原路径。有效范围围绕实际开合状态，不用独立计时器制造“抬盖中”。

用**已有同一份 character / presentedSoul** 得到完整盖、当前帽饰、手与身体主体的可见轮廓，再与当前拾光的实体轮廓合并。柔光晕、飘粒子不强迫扩大构图。设合并横向范围为 `[L,R]`，视野宽度为 `W`，CSS 留边换算为世界单位 `m`，则可行 camera 区间为：

`[R + m − W, L − m] ∩ [0, level.width − W]`

区间非空，并且身体主体仍在当前画面里可读，才属于本切片要保护的近身构图。它约束的是画面，不给角色增加世界位移、缩放或透明替身。

### 远行、活动与世界边界

拾光远行到身魂无法同框时，继续原灵魂跟随，允许身体正常离屏。`activityFramed`、月亮、失物及头盖活动的专用视图优先，不能被此规则覆盖。所有 pointer / DOM / 离屏提示必须使用相同的最终 camera，不能只改 Canvas 的一次 translate。

camera 仍限制在原世界范围。若身体靠在世界最边缘，完整服装本就无法容纳，应该退出保护或据实保留局部裁切，不能添加虚假的地面、拓宽世界或偷偷把身体移开。

### 连续性、resize、暂停与减少动态

目标是给**原相机目标**增加可行区间约束，并继续原跟随速度与原时钟。退出近身保护时从当前 camera 连续回到普通目标，不能直接恢复某个缓存旧 camera；重新进入时也不能突然向左吸回几十像素。需要对进入 / 退出边界留出几何缓冲或滞回，并验证不会左右来回拉扯；不为此新增一个动画时钟。

尺寸变化是独立边界：必须同时检查新尺寸的第一帧和随后稳定态。能同框时可修正已不适合新尺寸的当前 camera，但同一次投影中身体、世界、手、盖和拾光必须一起变化；不能只把角色推右。暂停且没有 resize 时完全冻结；暂停中 resize 只重新排布视野，不推进任何游戏时钟。减少动态沿用原直接落定规则，不增加缓动或回弹。

### 同一帧呈现对象的契约

优先复用原本已算出的 `character` 和 `presentedSoul`，只做少量边界数学。**不能在新增 camera helper 中再算另一套 rig / soul，也不能让 v33 小猫消费另一份对象。** 当前 base render 的 viewport 更新早于 character / soul 求值，这是正式接入时需要明确处理的调用顺序，而不是可以忽略的细节。

建议新建纯边界模块（如 `dream-cap-framing.js`），由现有相机 / 呈现入口提供同帧对象，回传约束或不参与结果；若需调整视觉调用顺序，应只在新工作树审阅该小范围接口变化。现有渲染、背景视差、裁剪、身体离屏提示、罗盘、pointer 投影和 DOM 避让最终必须看到同一个 camera。正式实现不能沿用本研究的“画完恢复 camera”技巧。

本轮不预先写运行时。下一步实现的主要工程风险正是：**在不重复求姿态、不破坏原跟随时间语义的前提下，把同一 camera 贯穿所有消费者。** 不应以一张离线好看的图替代这项集成验证。

## 后续只需围绕此切片验收

1. **补齐真实记录。** 320 / 390 原生浏览器从正常首章输入达到近身全开，保留自然耗能；另重放 1280→390→320。每次保存 camera、scale、viewWidth、viewportOffsetY、activityFramed、outfit、同帧 rig / shown、帽盖轮廓及原尺寸图。不要再从旧合成 PNG 反推 camera。
2. **动作完整。** 掀盖初段、中段、全开、归位、E 反转、两种朝向及实际帽饰，手 / 握点保持一致；帽饰与骨盖不脱节，脚、影子和真实平台一起投影。
3. **近远与边界。** 近身可同框时盖部完整且有合理留边；远行仍正确跟随拾光；进入与退出保护不跳变、不抖动。世界两端、resize 首帧 / 稳定帧、暂停中 resize 均记录实际行为，不能保证不可行情况下也完整显示。
4. **事实与输入不变。** 同输入的身体 / 拾光 / 小猫坐标和速度、碰撞、能量、机关、收集、cap 进度、存档和奖励与原逻辑一致。世界可踩面不改；活动点击投影和 HUD 角色避让仍与画面一致。
5. **原契约。** 桌面、节庆和活动专用构图保持；减少动态无新增动作；暂停无新增时钟；每帧同一 character / shown 对象继续被角色、拾光与小猫共用。边界判断用有限数学，不做每帧 Canvas 像素扫描。
