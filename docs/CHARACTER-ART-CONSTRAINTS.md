# 角色与游戏实景美术约束（强制）

本文件是《掀起你的头盖骨》角色设计、游戏内 Canvas 实景绘制、动作动画和自动迭代的强制美术约束。所有人工会话、自动迭代任务、代码代理、候选分支和发布验收均须遵守。与旧头像、旧立绘、旧预研图或历史分支中的角色设计冲突时，以本文件和用户批准的原始设定板为准。

## 1. 唯一视觉依据

- 唯一角色/场景基准：用户批准的原始 1536×1024 设定板 `docs/art-reference/approved-board.png`。
- 预期 SHA-256：`f728aa967f5ccd0fcb8a3ea2a13015f88e1904a293a77626a7770798a4891793`。
- 使用前必须确认仓库文件真实存在，并重新计算文件 SHA-256 与上述值完全一致。路径缺失、哈希不一致或只有缩略图/截图时，视为基准不可用；不得自行重绘一张相似图、用概念图替代或声称已核验。
- 不得将历史上的银发、湖绿围巾、小光灵等旧方案解释为符合新基准。
- “掀起你的头盖骨”是打开脑洞的比喻。严禁为主角制作头骨头盔或把角色设计成字面掀开头骨。

## 2. 主角不可变身份特征

### 阿拾

必须同时满足：
- 棕色短发；发型轮廓、发束层次和发梢方向清楚，不能用深蓝/银白头发替代。
- 自然、协调、可读的人脸；有明确的眼睛、眉毛、鼻部、嘴部和面部明暗结构，避免僵硬面具脸、空洞眼睛或过度夸张五官。
- 蓝色夹克；应呈现领口、门襟、袖口、衣褶、接缝和合理的受光/背光层次。
- 米色内搭；与蓝夹克分层清楚，不能合并成一整块色面。
- 旅行背包；背带、包体、厚度、扣件/拉链与身体遮挡关系合理，动作中保持稳定附着，不穿模、不漂浮。
- 角色气质是有亲和力、自然、灵动的旅行少年；姿态与比例须优雅协调。

### 拾光

必须同时满足：
- 长发；有稳定的发型轮廓、分束、发梢和动作惯性，不能以小光灵或无实体发光粒子替代。
- 红围巾；必须清楚可辨，围绕颈肩的穿戴关系合理，随动作有克制、连续的摆动。
- 米色外衣；领口、袖口、衣摆、衣褶和材质明暗清楚，与红围巾形成稳定配色关系。
- 必须是真正的人形女孩：具有完整头部、躯干、双臂、双腿和可辨认的手脚比例；不能退化为非人形光球、小精灵、幽灵光点或纯特效。
- 角色气质是温柔、灵动、有情感表现力的人类旅伴；表情、视线、动作应与对话和场景事件一致。

这些特征属于角色身份约束，不是某一套皮肤或可选外观。节日装扮、受光颜色和剧情状态可以变化，但不得遮蔽或改变角色的基本身份识别。

## 3. 游戏实景优先：必须改真实 Canvas 角色

- 角色美术的主要交付对象是玩家实际游玩时看到的世界空间 Canvas 人物，不是对话头像、档案头像、章节卡或单独展示立绘。
- 每批角色迭代必须明确指出并修改真实运行时绘制路径/资源/动作帧。应优先检查并按职责维护 `dream-traveler-face.js`、`dream-traveler-art.js`、`dream-engine-base.js`、当前正式引擎入口及相关 NPC/动作绘制模块；以最新 main 的实际调用关系为准，不得仅凭文件名猜测调用链。
- 角色头部、五官、头发、颈部、躯干、手臂、手部、腿部、脚部、服装、背包/围巾和阴影必须作为同一套实景人物构图协调绘制；明确前后遮挡、锚点、缩放、镜头投影和落地关系。
- 头像/肖像可以同步更新，但只能作为配套交付。只换头像、只换 SVG、只改资源 URL、只调色、只改版本号、只增加独立模拟画板，均不算完成角色重构。
- 不得把 96px 裁切合成图放大后称为高清全身角色；不得把低分辨率局部形变补间称为新绘高清逐帧动画；不得把程序化几何占位图称为精绘角色。
- 任何角色资源替换都必须核对实际加载路径、加载失败回退、解码完成时机和真实游戏截图；不得只检查资源文件存在。

## 4. 细腻度与美观度的长期优化方向

后续每轮自动迭代都必须把角色细腻度、美观度和实景一致性作为持续主线，而非偶发附加项。优先改进：

1. **脸部与表情**：脸型比例、眼距、眼睑、眉形、鼻部体积、嘴角、耳部、肤色层次、面部受光；表情要自然、克制、可读，不同情绪之间保持身份一致。
2. **头发**：主轮廓、发束分组、发梢、遮挡、边缘质量和动作响应；避免锯齿、塑料块、过度高光或无方向噪声。
3. **服装与配件**：布料厚度、缝线、领口、袖口、衣摆、褶皱受力、背包带/围巾连接点；保持角色特征色并形成材质层次。
4. **人体比例与姿态**：头身比、肩宽、躯干、手臂长度、手掌、腿长、脚掌和重心关系自然；站立、转身、伸手、抱物和落地姿态必须可信。
5. **光影与材质**：统一主光方向；角色受环境光、暖色灯光、树影、海岸蓝光和舞台光影响时有细腻变化，但不能改变固有服装颜色；脚下阴影应投向真实可承载表面。
6. **整体协调**：线条粗细、轮廓清晰度、色彩、明度、饱和度、材质细节与现有场景一致；角色应融入背景而不是像贴纸悬浮在场景上。

每次只选择一组可完成、可验证的真实改进；不得为了追求细节破坏轮廓识别、动作可读性、性能或原有玩法。

## 5. 动作与动画约束

- 角色动作必须来自真实游戏状态：移动速度、方向、地面接触、腾空、落地、平台附着、互动目标、手持物和剧情阶段。不得只按固定计时器播放与物理状态脱节的动画。
- 持续完善待机、呼吸/眨眼、走路、跑步、起跳、上升、下落、落地缓冲、转身、交谈、伸手、拾取/持物、拥抱/归位等动作。动作帧需保持人物比例、服装结构、面部特征和配件锚点一致。
- 优先使用经过设计的关键姿态和有明确轮廓的连续帧；可用插值平滑帧间运动，但不能用局部拉伸/扭曲冒充高质量逐帧动画。
- 发梢、围巾、衣摆、背包带等次级运动必须有合理延迟、幅度和阻尼；禁止抖动、穿模、漂浮或突然跳位。
- 动画必须尊重暂停：暂停时冻结动作相位、粒子与演出；减少动态模式使用清楚、稳定的静态姿态/淡入淡出替代，不得补播暂停期间积累的动作。
- 不新增按键、改变碰撞盒、移动速度、跳跃初速度、平台物理、危险阈值、谜题解锁或存档/奖励语义来掩盖美术问题。保持既有六章、十节日、旧游戏和全部原有交互。

## 6. 每轮角色验收门槛（不可降级）

每轮候选验收除原官方逻辑/资源/网络/物理测试外，必须增加以下角色检查：

- **身份检查**：阿拾棕色短发、自然人脸、蓝夹克、米色内搭、旅行背包全部可辨；拾光长发、红围巾、米色外衣、完整人形女孩全部可辨。
- **实景检查**：截图必须来自真实游戏 Canvas 和正式页面运行路径；不得用头像、独立画板、离线合成图代替。
- **细节检查**：正面/侧面或转向、至少一种移动姿态、至少一种跳跃/落地姿态、至少一种互动姿态，检查五官、服装、配件和遮挡是否一致。
- **视口检查**：真实候选 Chromium 至少覆盖 1280、390、320 宽度；核对角色比例、裁切、清晰度、场景光影和输入可用性。模拟触摸不得冒充实体手机/Safari/GPU 验收。
- **对照检查**：与上一稳定版本同视口、同场景、同动作做前后对照；必须有明确可见的质量提升，不得只靠版本字符串或缓存参数制造“变化”。
- **回归检查**：角色绘制不能破坏碰撞、落地、平台承载、危险冻结、剧情逐页 speaker/image/text/ready/decode、暂停/减动、解锁、存档/奖励、ARIA/语义和精确网络账本。
- **诚实记录**：记录本轮真实改动文件、资源尺寸/来源、候选 SHA、测试结果、截图证据和未覆盖设备范围。96px裁切、重采样背景、补间帧等必须如实标注来源与限制。

任一身份特征缺失、游戏实景未改变、角色质量没有可见提升、真实候选浏览器失败或证据不足：本轮角色优化不通过；不得合并/部署，不得报告已完成。

## 7. 自动迭代的优先级

- 每轮自动迭代都要先检查当前角色质量差距，并优先处理能明显提升游戏实景角色细腻度/美观度的一项工作。
- 角色实景的优先级高于单纯版本号推进、重复审计脚本、只换头像、与角色无关的装饰性小改动。
- 在角色达到稳定的高质量基线后，继续在六章 NPC、互动姿态、剧情插画和场景光影中保持同一艺术标准。
- 每轮都要记录“本轮角色质量改进点”和“仍待改进点”，不能把长期目标误写为一次完成。
- 开发与发布严格遵守 `docs/PROJECT-CONSTRAINTS.md`、`docs/ITERATION.md` 的唯一分支、完整候选、同轮部署和正式 HTTPS 验收规则。
