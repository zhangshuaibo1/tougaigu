## 一组相互配合的画面与互动改进

### 1. 三层藏书室，整幅构图先成立

远层保留鲸落的尺度感：青蓝海雾、完整而克制的鲸骨拱架、少量透过拱隙的光。鲸骨用温冷分明的体积和接合阴影形成大轮廓，避免又叠一条同样抢眼的巨鲸。中层是后退的藏书龛、弧形立柱、深色木料与布面书脊；让入口的蓝页、第一灯附近的阅读高窗、风廊后的第二灯形成依次出现的焦点。近层只在地面以下或屏幕边缘补少量材质，保持角色、脚下表面和前方路线清楚。

建议下一轮使用原创精绘位图承接大面积背景材质；可调用 imagegen 生成宽幅、无文字、无角色、无玩法物件的鲸骨藏书室，再以实际视口和视差布局检查裁切。不要直接拿概念图覆盖画布。背景由 `cameraX`、`worldWidth` 和真实 `viewport` 布局，必须检查镜头最左、中段、最右及手机上下裁切，不按某一张桌面截图写死位置。

**位图只负责不可交互的远景与建筑。**阿拾、拾光、蓝页、两本浮书、固定平台、谜灯、记忆、目录门、危险物、出口、风廊、头内活动及失物互动仍由程序读取真实状态绘制。画中不能包含另一组亮灯、门、悬空踏板、漂浮角色或可收集亮点。真实物件及其提示始终位于背景之上。

原程序背景有巨鲸影，世界建筑层另有鲸骨；新图成功显示后，仅条件性跳过已经被它替代的装饰建筑，避免两套轮廓重叠。加载中或绘图失败时立即保留完整原程序背景与建筑，不能留下空幕。

### 2. 真正可踩的书，兼顾材质与落脚可读性

为第四章新增纯绘制平台分支：书封采用深青或淡紫织物、压边与少量黄铜护角；侧面用明暗分层表达纸张厚度，固定书架承载面用暖木边与阴影收口。书脊和纸边的节奏在正常手机比例仍应可见，不靠密集小字。

所有承载面严格取传入平台的 `x..x+w` 和 `p.y`。顶部不整体旋转、不外伸出另一条似乎可踩的亮边；装饰厚度向下画。浮书跟随真实 `movers` 的竖直运动，材料上的高光与书一起移动。接触阴影只能来自真实可站立表面；不新增起伏、托举、额外晃动或磁吸。风廊的少量弯线沿现有风向经过书页空间，颜色与谜灯、记忆区分，减动时保留静态方向线。

目录门可增加薄框、书签形刻痕和黄铜边的材质，但其开启事实只读 `barrierOpen(gate)`。已开启的帷幕不能仍画成厚实封闭书墙，也不能提前变成开放通道。出口与未收集记忆保持原有形状和位置，不在背景里再画一个“出口”。

### 3. 蓝页有呼吸，伙伴进入同一片光

在现有小鲸轮廓内补水润蓝灰背部、暖灰腹部、半透明鳍缘和圆润尾部的体积。浮书增加布封、厚纸、书槽阴影与一页干净留白；眼睛和嘴保留足够明暗，让 320px 上的表情仍能辨认。减少循环气泡，避免夺走拾光和谜灯的注意力。所有姿态保留现有 `STORY_NPC_BOUNDS`（左 -46、右 46、上 -134、下 7）并用实际像素边界检查，不能只检查常量未改；名字与 Q 提示继续清楚。

沿用 `getStoryNPCView()` 的 `near / talking / look / capOpen / form / seals`：身体靠近时注视阿拾；真实掀盖时，书随实际开盖程度略抬、翻开，目光转向拾光；交谈时书页收稳；本局双灯后留一个安静笑眼。翻页、鳍尾与呼吸只使用已有 `t/visualTime`，暂停冻结；减动时不推进装饰时间，动作直接取稳定姿态。不能仅进入场景就自动表演“借阅成功”，也不能把开盖次数变成新任务。

把已有阿拾精修材质和拾光纯绘制以 `mode==='story' && chapterIndex===3` 接入第四章，让蓝页、主角与背景的完成度一致；利用真实地面或浮书计算影子和海光反射。保留原统一头盖 rig、真实灵魂 presentation、携带物与前缘遮挡。**v25 的第三章乘台动作仍只属于真实 `stage`，本轮不把浮书冒充舞台，也不直接扩展新的跳跃/落地表现范围。**前两章和第三章的现有输出保持。

### 4. 两盏灯照出故事，保留真实 clock 选择

把本局 `lanterns[0].lit` 与 `lanterns[1].lit` 分别映射到两个背景阅读区：第一灯让近目录门的高窗和暖纸边显出来；第二灯给风廊后的书龛留一小片暖光。若需要渐亮，只在现有 playing 更新中推进两个表现量；暂停保持、重开归零、减动直接落到实际目标。只亮第二灯的隔离测试不能照亮第一灯区域或打开目录门。既有「高窗望远」「书签留页」小景继续由原答题事件触发，保持原位置保护和一次性规则。

这里的情绪是“昨天可以被好好放下，路仍然通着”。不增写一段 HUD 解释，不在游戏中伪造第三个选项。当前 `clock` 只在第四章实际完成后由原来信流程打开：`release` 是「把它还给钟声」，`hold` 是「留下一页安静的地方」。不改选择 ID、答复、`chooseStoryReply()`、结局映射或存档结构；不由灯数、开盖、旧收藏推定玩家选择。

本轮不要求再实现一套 clock 选择回响。应先把已有真实选择及其保存路线纳入验收；后续若专门做选择后的场景差异，另行明确从已保存 `save.choices.clock` 读取的展示接口，不能把当前尚不存在的接口当成已有能力。

**先建立实际路线与改前原尺寸截图，再做美术。**离线绘制可以使用明确标注的姿态夹具；浏览器主路线只能通过原按钮、键盘或触摸输入推进，读取状态用于判断，不能改角色坐标、谜灯、选择、解锁或 localStorage。

## 发布前必须回答的验收问题

- **完整画面是否真的提升？**入口、第一本浮书、目录门、风廊第二灯、出口分别有改前/改后同状态整屏；桌面和 320 均能分出远景、中层建筑、可玩表面和角色。蓝页眼睛、浮书纸层与脚下接触在正常比例清楚，背景没有重复巨鲸或真假踏板。
- **物理是否保持？**对第四章用相同正常输入并行运行基础引擎和整合引擎，比身体/灵魂、两本书的位置与附着、能量、门、谜题事件、死亡恢复和一次结算。实际浮书承载面仍等于 `p.y`，角色鞋底不浮不穿；掀盖抓点与返回遮挡保持原 rig。单元姿态夹具不能代替这条路线。
