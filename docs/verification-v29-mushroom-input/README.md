# 第六章蘑菇与根台：正常输入的离线复核

这是对候选四失败后控制路线的离线分析，使用候选 `172bde595381dc21193563d8587fdd9d6c9e7df4` 中的真实生产引擎。**控制延迟是合成参数，不是对失败的 390 px 浏览器时序的重建。** 第四候选没有保存那一次蘑菇弹起到根台失败之间的完整观测，因此本分析不能为该次运行补出历史事件、pointerId 或具体弹起时刻。

## 方法与边界

每个案例都从第六章原始出生点正常开始。脚本通过 `setInput`、`jump`、`toggleSoul`、`pulse`、正常谜题回答回调 `resolvePuzzle(true)` 和 `recall`，先踏板点灯、收集前两枚记忆、搭乘一整周期浮书，再跳到右岸。没有给身体坐标、速度、平台、谜灯、死亡数、存档或物理常量赋值。离线时间通过引擎原有的 `update(1/60)` 推进；这不是浏览器或实际设备测试。

三个策略各跑同样的 80 组参数，共 240 条完整正常输入轨迹：

- 控制轮询间隔：2、3、4、5、6 个固定步，约 33–100 ms。
- 输入往返/释放延迟参数 gap：0、1、2、3 个固定步，0–50 ms。在 steer 中是输入已生效后的等待，在最终释放处是 ready 决策后、setInput(0) 前的延迟。
- 段间处理时间 handoff：0、2、4、8 个固定步，0–133 ms。旧路径在分段之间消耗，新路径将准备等待放在唯一持续按住方向之前。

这些是固定步下的确定性参数网格，不是设备失败率。poll 只限制控制决策的检查节奏；bounce 与 landing 证据仍由 observe() 在每个 1/60 物理步锁存，未模拟浏览器 RAF 丢帧或协议观察漏采。因此80/80证明的是这份正常输入和合成延迟模型中的路线余量。

| 策略 | 满足原根台落地条件 | 最终全身宽度位于 1600..1730 内 | 结果 |
|---|---:|---:|---|
| 原 1420→1440 制动、锁存弹起、释放后再驱动 1680 | 71 / 80 | 未作为该策略的通过条件 | 8 次停在 x=1585 / y=560 的左墙；1 次已到 y=390，却因目标附近反向振荡超时 |
| 一次持续向右直到观测到根台着地，再释放 | 80 / 80 | 12 / 80 | 自然刹停最右 x=1732.42，缺少整身台面余量 |
| 一次持续向右到 x≥1660 且脚点 y≤390，再释放并自然落稳 | 80 / 80 | 80 / 80 | 采用此策略；最终 x=1676.42–1700.42，身体右侧至少保留约 14.58 世界坐标单位的台面 |

原策略有 12 例在最后一次 hold 之前已真实弹起；代表失败在 `drive_to(1440)` 制动回转期间触发 `vy=-850`，随后继续回到 x≈1430。重新向右时，飞行已消耗约 0.317 秒，最终停在根台左墙。这证明旧控制代码确实存在该路径，**不能据此追认失败浏览器运行必然经过同样时序**。

采用策略的全部 80 例中，从唯一持续右输入开始，真实弹起出现在 0.183–0.250 个模拟秒，根台首次着地出现在 1.183–1.250 个模拟秒；最终均为同一身体、零死亡。浏览器仍独立要求 native down 后真实 `vy < -800` 在 2.8 秒以内、根台自然落稳在 6 秒以内，并验证 down/up、首次地面接触、全身支撑与观察器清理。离线成功不能代替这些实际浏览器断言。

## 保留的证据

- `original-analysis.mjs.txt`：产生本批原始轨迹的原脚本文本。
- `normal-input-analysis.mjs`：可移植运行入口，保持相同策略与物理输入；仅调整生产引擎相对导入、导出单例函数，以及作为模块导入时不自动运行矩阵。
- `summary.json`：三个策略的 80 组结果、时刻与位置范围、8+1 失败分类。
- `old-approach-wall-failure.json` 与 `continuous-release-success.json`：同一组参数的原始失败、成功轨迹，包含每步实际身体状态和正常输入命令，便于直接审阅。
- `all-synthetic-delay-traces.json.gz`：全部 240 条原始 JSON 的无损归档；Gzip `mtime=0`，没有文件名头。
- `source-runtime/`：实际使用的三个核心引擎/关卡源文件原字节副本。`manifest.json` 同时记录当时全部 67 个生产 JavaScript 源文件的 SHA-256、引擎 commit、证据文件散列和压缩参数。

## 复现

使用 manifest 记录的生产引擎版本，并核对源文件 SHA-256 后，在仓库根运行：

```sh
node docs/verification-v29-mushroom-input/normal-input-analysis.mjs
```

完整矩阵写到 `/tmp/tougaigu-v29-mushroom-input-analysis.json`。其中所有时刻、轨迹均来自该次离线引擎运行。持续集成只保留两项具体回归：1440 制动回转消耗弹起，以及根台上的 1680 目标振荡；不把整套 80 组矩阵扩为长期浏览器负担。

## 真实浏览器验证的边界

成功必须保存真实原生 down/up。普通条件检查或超时失败由共用 hold 的 finally 发送释放；本轮没有扩修或验证 Playwright/CDP 传输本身异常时的释放保证。失败记录若缺少 releaseInput 会保持缺失，不补造事件。observerCleanup 只证明该段 RAF 和观察器已移除，不代表原生输入已经释放。
