# PLAN-v30 · 脚下有回声：六章动作连贯

**状态：下一轮设计，尚未修改运行时代码、尚未验收或发布。** 本计划在v29候选CI `40906289105` 运行期间形成。开始实施前，先核对最新远端refs、v29最终QA与在途登记，收尾已开始的候选/公网验收；以最新成功版本为改前基点，不能把本文件视为v29已通过或v30已实现。

## 为什么做这一轮

六章已经共用精修后的阿拾和拾光，但角色对同一物理动作的反应不一致。下一轮把现有第三章验证过的升降、落地收势和站稳动作延伸到其他主线章节，让玩家更容易看清“正在起跳、准备落脚、已经被平台带着走”。这是现有玩法的表现改进，不引入新的技能、操作、奖励、存档字段或关卡门槛。

## 一组相互配合的改进

### 1. 主线六章使用同一套真实身体表演

将作用域改为**明确的story模式、整数chapterIndex 0至5**。起跳、下降与0.2秒着地收势复用已有逻辑；第三章原有数值与画面必须保持一致。第1/2/4/5/6章由同一个 `getCharacterPresentation()`、同一份 `performance` 和现有 `getTravelerMotion()` 消费，不新增第二套手、头、帽盖或覆盖在人物外的图层。

新可见变化：踏上站台前自由手臂随真实上升收拢、下降时准备接触；落上书页、岸台或树根后短暂屈膝、衣摆和邮包回落。普通跳跃和蘑菇上弹都来自实际 `vy`；蘑菇已足够体现更高的起跳，本轮无需再加一套“弹床技能”或装饰粒子。

保持 `applyTravelerPerformance()` 既有手部混合：左手握盖、右手扣盖/接住拾光优先，只有未被占用的手臂参与平衡；`rig.bodyMatrix/headLocalMatrix/capLocalMatrix`及盖沿、掌心、灵魂入口锚点完全沿用现有rig。全量张盖、归位、空中E反转时不能把手从铰链拉开。

### 2. 让横向浮台与纵向浮书各自有可信的站稳动作

合法支撑仅来自 `context.movers` 中本局真实的 `stage/book`：必须同时满足body grounded、真实platform ID、脚高与平台顶面一致、水平接触。静态书形装饰、邻近平台、失去接触的旧ID、作者静态 `level.movers` 都不能触发。

- **第三章stage、第六章last-stage横移：**保留真实 `dx / consumedDt` 驱动的轻微左右平衡。玩家停住时双脚不踏步；移动台带着人物移动，不改变 `body.walk`。往返换向必须跟随本步位移自然过零，不叠加正弦摇晃。
- **第四章book-a/book-b纵移：**独立读取 `dy / consumedDt`。用小幅、有限的膝部与自由手腕调整表达“上托/回落”，保持脚底仍在真实书页上，不把竖直速度塞进水平 `balance`。本轮可新增只读的 `platformVerticalVelocity`/轴向字段，但保留现有 `platformVelocity` 的水平含义，避免破坏第三章现有证据。
- **静止、转向、暂停与减动：**附着事实可保持 `phase:'ride'`，装饰幅度在减动时全为0；平台仍按原物理运动。暂停后本步dx/dy、视图与完整Canvas冻结，不能在暂停读取时重新从墙钟算速度。

不要修改脚底的世界坐标，也不要整体拉伸/压缩rig来制造承载感。使用已经存在的腿部关节与自由手臂；对所有实数输入有限校验，对位移速度和姿态幅度有界处理。没有数据时回到静态姿态，不由装饰时钟补造“正在移动”。

### 3. 补齐最早两章的真实落点阴影

复用 `getGroundShadowView({body,level,movers,closedBarriers})` 和已有绘制。第一章的单向踏台/关闭帘幕、第二章树根高台等，阴影落在身体下方最近合法支撑面并被其几何裁剪；上升后淡且小，接触时回到现有着地影。无合法支撑面时返回null，不能把阴影画在空隙上。

这是同一轮“脚下有依据”的配套，不增改碰撞体、地形、镜头、背景、美术资源或全局灯光。新差分范围只允许人物已有包围范围与明确记录的支撑面阴影区域；第三章及之后的旧阴影像素应保持。

## 实现边界与易错点

1. **主引擎不改。** `dream-engine-base.js`、`dream-levels.js`、存档/结局/奖励映射保持原字节；扩展展示层和其接入即可。`frame`仍是唯一原始固定步循环，使用真实消耗dt（最大0.04）与visualTime，无新增RAF、interval或性能时间推演。
2. **落地是一次真实事件。** 原有条件“同run、同body、同死亡数、前后均body形态、之前离地且vy>0、之后 grounded、存在真实支撑”继续保留。走上同高平台、出生、暂停、灵魂操控时身体自然落地、死亡重生、羽毛护符替换body都不能伪装成新收势。
3. **蘑菇不要误判。** Base在同一步接触地面后可立即给出 `vy=-850`、`grounded=false`；本轮应该显示实际上升，不插入一次不存在的“已经站稳”动画，也不能延迟上弹。
4. **生命周期保留。** 开始/重开/换章/死亡/销毁即时失效旧表演；暂停冻结；打开减动立即清除尚未结束的落地收势，关闭减动不补播。回调导致新run或destroy时仍先检查现有生命周期guard。
5. **既有内容互不干扰。** 第一章真实去程票、第二章种子归位/生长与letter回响、第四章浮书/书页场景、第五章clock回响、第六章晨光印记均保持原接触与抓握。节日chapterIndex虽然可能为0，必须由mode严格隔离，不能误继承主线表演。
6. **旧断言要按新合同更新，不删空。** `tests/traveler-performance.test.mjs` 当前对0/1/3断言view=null，`scripts/browser-smoke.py::validate_traveler_pose()`对非第三章断言null；这些应变成六章明确正例、十个节日/非法上下文明确负例。`ride`不能再无条件断言platform='stage'，应核对当前章节真实允许的mover ID、类型、轴向和几何。严格跳跃采样器的阈值、顺序和清理不变。

## 改前基线与自动验证

先冻结**最终成功v29**的源码SHA及其原始图片/输入，不以正在跑的候选冒充已发布基点。可直接复用已有第四章路线、`docs/v27-baseline`海岸和`docs/v28-baseline`邮局的正常输入tape；比对到当前v29后再用于v30。原基线与v29实际运行若不相等，应先解释差异，不能静默重录来掩盖物理变化。

### 必须有的逻辑/离线检查

- 六章逐步与冻结v29及BaseGame对照body/soul、输入、time、能量、movers、灯、记忆、hazards、checkpoint、粒子、回调、一次结算。允许变化的只有本轮纯展示状态/绘制；所有控制通过原方法，不注入坐标、platform、grounded、灯或存档完成状态。
- 第三章原有跳跃/承载姿态保持数值一致；其严格单跳、0.2秒收势、抓盖/接住手和脚底断言保留。
- 第四章两本书至少完整周期，真实dy正负都覆盖；第六章横书完整往返覆盖。确认脚底世界y等于实际平台y、零输入时相对位置仅有原浮点误差、body.vx和walk不被平台运输伪造。
- 第1/2章普通跳跃与第2/6章真实蘑菇上弹、树根台接触。不能只对一个空mock Canvas声称美术通过。
- 暂停、减动开关、早反转E、低能量拒绝、灵魂出体时身体落地、普通死亡与无死亡计数的羽毛保护、同章重开、换章、销毁、零/负/非有限dt及回调重入均有实际边界反例。
- 用真实Canvas输出1100×640、390×595、320×431的起跳、下降、着地0/6/12帧、横书左右行、纵书上下行与转向图。比较改前/改后且至少一组用renderer ablation对比相同物理帧；手与铰链接触、脚底位置和有限差分区域实际检查。
- 低端性能不凭空宣称。只报告同设备同帧的绘制调用/耗时和新增循环有界性；新展示不新增资源请求，已有图片失败/迟到流程应继续通过。
