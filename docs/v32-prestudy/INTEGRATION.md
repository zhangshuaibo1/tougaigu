## Canvas / 控制区：同 DOM 的旧 CSS 消融对照

每个独立 context 在任何开盖输入前读取当前几何，然后在**一个同步 evaluate** 内，暂时停用当前两份已加载的 `CSSStyleSheet`，在各自原级联位置插入上述 v31 基点的原始 `dream-play.css` 与 `cap-play.css`。为中性新包裹额外设置 `.stage-communications{display:contents}`。读取实际 DOMRect、Canvas 绘图缓冲、computed CSS 尺寸、transform 链和控制节点集合/显隐/矩形，最后在 `finally` 中恢复原样式表并移除临时样式，再次读取恢复后的几何。使用 `sheet.disabled`，不切换会产生异步重新应用行为的 `link.disabled`。

原 CSS 字节和 SHA256 保存在 `tests/fixtures/v32-layout-v31-css.json`，加载时核验；本地夹具同时固定正式基点和两份摘要。配对明确记录为 `same-current-DOM-original-v31-CSS`，仅核对采样中 Canvas/控制区是否保持，CSS 矩形容差 0.5px，缓冲尺寸和 transform 链严格一致。

**这是同一新版 DOM 上的旧 CSS 消融，不是运行旧完整发布版。** 页面版本元信息始终是真实 32.0.0。同步消融期间没有动画帧或新的引擎 resize 回调机会；DOMRect 会强制计算真实布局，buffer 为当时实际读数。它不证明跨版本物理、功能、所有姿势或性能相同。当前按钮在视口内、控制中心可点这一检查也单独标明，不能代替真实配对。

## 本地验证

首次完整 `npm test` 在当前 Node 环境报告 **76 个测试文件全部通过**，对应首个 `6be11a3` 冻结前的代码；该文件计数不与 CI 的单项测试计数混用。修复 CSS 恢复工具后先做局部几何、语法和真实浏览器验证，完整浏览器结束后再对最终代码重新执行全量测试与静态检查。两轮日志和各自源码范围分开保存，精确结果见 [integration-review.json](integration-review.json)。

新增几何单测只给纯验证函数输入独立的几何夹具，证明它能拒绝 Canvas buffer、控制位置、断点泄漏、输入遮挡及 CSS 来源损坏等负例。夹具从未进入游戏或浏览器，不构成真实布局通过。

首次冻结 `6be11a3` 时的环境检查：当前 `python3` 与主 Python 运行时均没有 Python Playwright；主 Node 运行时有 Playwright 包，但其指定的 Chromium 可执行文件不存在，系统命令和浏览器缓存也未找到可用 Chromium。之后按根会话授权，在 `/tmp` 隔离安装了 Playwright 1.55.0 和 Chromium Headless Shell 140.0.7339.16；没有改全局配置。

首次真实矩阵执行揭示了测试工具自身的同步恢复缺陷：900×800 的旧 CSS 消融配对相同，但 `link.disabled` 恢复后样式在同步任务内尚未重新应用，恢复断言正确失败为 `Canvas changed top`。原始失败证据保留在 `/tmp/v32-layout-verification-6be11a3`，没有计为游戏通过。已修正为切换加载后的 `CSSStyleSheet.disabled`，仍保留严格的配对与恢复检查。首次截图还暴露本地无中文字体；随后在 `/tmp` 解包官方文泉驿正黑字体，通过本次浏览器进程的 Fontconfig 路径启用，未修改生产 CSS 或系统字体。修正后的真实结果以相应冻结源码的独立执行记录为准。
