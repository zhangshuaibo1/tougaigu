## 温室原问题的真实前后观察

根会话亲阅了 [历史原问题 PNG](before-greenhouse-root-crossed.png) 与 [当前温室根台 PNG](evidence/local-5445a39/1280-greenhouse-root-crossed.png)。旧图的对白卡实际遮住阿拾的头脸；新图的同一句“叶子探出头了，盖子得给它留点地方。”位于左上，头脸、身体和脚底可见，右侧目标与检查点公告清楚。

当前同步快照的对白、HUD、目标、公告及操作区布局检查通过，真实 rig 投影中的脸、骨盖、上衣和双脚没有与对白卡相交。它与同次运行站台参照的 Canvas/控制区几何也匹配。原温室根台通行保持零重生/无死亡门槛，实际自然对白没有通过重放、改原计时或强制显示制造。

**两张前后 PNG 来自不同的真实运行时刻，不是像素同帧、受控 A/B 或所有场景的证明。** 每份同步几何和随后 PNG 也不是同一帧；装扮附属物、全部高位平台及完整透明轮廓仍不在保守主体盒的证明范围中。

## 边界、减动与实际公告共存

根会话还亲阅了 900×800 opening、[900×520 opening](evidence/local-5445a39/900x520-opening.png) 和 [899×800 ticket](evidence/local-5445a39/899x800-ticket.png)：中文可读，900 矮屏的主体/脚底及操作区可见；899 仍是原居中下方对白，不能标成新版全宽适配。系统与游戏减动两种真实设置均验证了零对白过渡，保留 [系统减动抱票原图](evidence/local-5445a39/1280x800-os-reduce-ticket.png) 作为代表。

此前准备阶段的 `notCovered` 把所有自然对白/公告共存都列为待验，实际证据现已收窄这个缺口：

- 900×800、1024×640、900×520 的首站 opening JSON 同时采到两段原对白与 `announcement.visible=true`。公告原文是“「掀开头盖骨」 · 让拾光去找上方的去程票”，属于自然退场窗口；随后 PNG 中它可能已经淡出。
- 温室根台 JSON 同时采到自然叶子对白与“暖灯记住了这里。散架后，会从这里再出发。”检查点公告，随后原 PNG 中两者也可读；它们分列且布局验证通过，仍不称同帧。
- 截图的“南瓜夜邮”是目标区季节活动徽记，与 `stage-announcement` 是不同节点，未把它误当公告原文。

原报告和原生成器保持当时的真实字节，不为一句规划缺口重写浏览器执行版本。以上说明澄清该句过宽措辞；**最长剧场双段对白加公告、大字体偏好、高位平台、排除模式跨布局比较及实体设备仍待验。**

## 配对范围与失败记录

六个独立 context 的 Canvas、buffer、控制节点集合/显隐/矩形，在同一新 DOM 上使用两份精确 v31 CSS 的消融对照中均匹配，恢复后也匹配。该操作只改变隔离测试 context 中的样式表，并在同步 `finally` 恢复。它不是运行旧完整发布版，更不证明所有游戏状态或性能一致。具体 CSS 来源、SHA256、测量和 0.5px 矩形容差均保留在原报告。

第一个冻结树 `6be11a3af80320a62ca78d400d04cf4c00323e7a` 的首次真实验证正确抓到了测试工具自身的恢复问题：`link.disabled` 的重新启用没有在同一同步任务内恢复样式。该失败 [报告](evidence/local-5445a39/initial-failure-report.json.gz) 和 [原日志](evidence/local-5445a39/initial-failure-log.txt) 保留；修正为已加载 `CSSStyleSheet.disabled` 后才进行上述两次成功执行。没有降低恢复断言，也没有把失败截图算作通过。

本地最初没有 Python Playwright 或 Chromium；随后在 `/tmp` 隔离安装 Playwright 1.55.0 与 Chromium Headless Shell 140.0.7339.16。首次图片暴露无中文字体，随后将官方文泉驿字体解包至 `/tmp`，只在测试进程使用 Fontconfig 配置，未改系统配置、生产 CSS 或游戏状态。当前结果对应这一具体环境，不代表所有字体环境。
