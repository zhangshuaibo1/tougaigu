## 每份证据能说明什么

[browser_dialogue_v32.py](../../scripts/browser_dialogue_v32.py) 读取实际 DOM 矩形、可见文字节点的 `Range.getClientRects()`、滚动尺寸、祖先 overflow 剪裁范围、真实控制中心命中、对白语义与当前引擎展示数据。

在 ≥900px 的普通故事范围内，新增验证检查：

- 当前可见 HUD、目标区、公告与对白卡互不相交；它们与当前可见的游戏操作按钮也不相交。
- HUD、目标、附近提示、可见公告与对白文字没有横向/纵向溢出、ellipsis、行数裁切，采到的文字行位于原内容盒、祖先 overflow 范围和视口内。对白段落保持至少 12px，头像保持至少 48px 的实测范围，原唯一 live region 属性与点击穿透保留。
- 若采到对白，以实际角色 rig 和渲染变换计算骨脸、骨盖、上衣和两只鞋的保守范围，并确认该时刻的对白卡没有覆盖这些范围。
- Canvas / 控制区与本次运行的站台初始采样比较：原 CSS 矩形（0.5px 容差）、绘图缓冲尺寸、引擎记录的 CSS 尺寸、CSS transform 链，以及所有采集的控制节点集合、显隐和矩形均需匹配。

**这份参照是同一次运行的不同正常对白状态，不是 v31 改前版本。** 没有提供真实参照时明确输出 `not-compared`，不能由源码未改推成“浏览器已测前后相同”。独立纯函数 `compare_surface_geometry(before, after)` 可用于之后真实取得的 v31 / v32 相同视口采样；它不要求两份版本号相同，但会拒绝视口、Canvas 缓冲、控制集合或矩形变化。正式发布前仍需准备这组真实跨版本配对数据。

## 投影的准确范围

骨脸、骨盖与衣身范围分别经过当前 `headMatrix`、`capMatrix`、`bodyMatrix`。两只鞋读取原 `getTravelerMotion()` 的真实 foot 坐标与角度，先做鞋局部旋转，再经过身体矩阵。之后沿用引擎真实 `camera`、当前 shake、`scale`、`viewportOffsetY` 与 DPR：

```text
screenX = canvas.left + dpr × scale × (worldX − camera + shakeX) × canvas.widthCSS / bufferWidth
screenY = canvas.top + dpr × (scale × worldY + viewportOffsetY) × canvas.heightCSS / bufferHeight
```

最后的缓冲比例保留 `Math.round(cssSize × dpr)` 的影响，不能再乘一次 DPR 或把世界坐标直接当 CSS 坐标。若 Canvas 或祖先带有 CSS transform/translate/rotate/scale，当前检查拒绝继续使用这个轴向投影公式。

局部区域是包住原骨脸/骨盖/衣身/鞋路径及描边的保守盒。它们**不是透明像素轮廓，不包含所有帽饰、围巾、邮包、效果或阴影**；因此检查说明的是该次采样中这些主体区域与对白避让，不是所有角色动作、装扮和场景都永久无遮挡。

所有布局和引擎数据在一次同步 JavaScript 调用内读取。后面的原有截图可能已经进入下一帧，证据明确 `geometryIsSameFrameAsScreenshot=false`；没有暂停或锁帧来伪造同帧图。截图路径标注为随后原流程将生成的文件，校验失败时它可能尚不存在。

## 成功与缺失都立即保存

`capture_dialogue()` 在检查成功或失败时立即写出 `<label>-dialogue-layout.json`，保留完整原始 snapshot、校验结果、尺寸比较状态与随后原截图文件名。失败保留原证据后抛出错误，不重新输入、重放对白或放宽断言。

抱票与温室目标点要求自然对白可见。若其在读取前已经自然结束，就明确失败为 `required naturally triggered dialogue was absent`；这表示所需视觉证据缺失，不能直接据此判断游戏对白计时有错。后续应读实际失败记录并调整独立采样位置，不能改生产时长来拍图。

手机宽度及排除模式返回明确 `outside-desktop-scope`，不声称做过角色避让。原手机 HUD 全文/按钮检查仍按原函数执行。目标点若本来要求桌面普通故事，却处于排除模式，同样不会冒充成功样本。
