原准备阶段运行了仅检视背景的 Canvas 脚本，生成 **13 张独立裁切预览、5 张并排比较图**。原布局报告完整保留为 [crop-report-v26.json](crop-report-v26.json)，没有把这些预览 PNG 批量归档。以下观察属于该次准备检查，不是本次重新执行的游戏验收。

- 390×595、320×431：各有左、中、右和两处暖窗中心共五张；窄视窗中仍保留骨拱或书龛主体，下部雾区未消失。暖窗中心的单独采样确认其在手机宽度下仍是完整窗格。
- 原准备者逐一目视了完整原图，以及上述五张包含全部独立裁切的比较图。未为审美展示做局部修补或增强。
- 裁切假设：背景显示为世界尺寸 2400×800、y=-52，以 `scale=预览高度/640` 显示；左中右取原图可视范围的 0/50/100%。手机高度沿用先前离线检查尺寸。**这些假设尚未成为第四章生产布局；不是当前游戏相机视差、真实网页 HUD 或实体手机截图。**

可复跑脚本为 [inspect-crops.mjs](inspect-crops.mjs)。从仓库根目录运行：

```sh
node docs/art/library-v26/inspect-crops.mjs --output /tmp/library-v26-inspection
```

脚本从自身目录读取归档 WebP；用脚本的绝对路径也可从其他工作目录运行。依照项目已有离线绘图脚本，依次在仓库、调用目录及 `CODEX_PRIMARY_RUNTIME_NODE_MODULES` 中查找 `@napi-rs/canvas`。省略 `--output` 时新建系统临时目录；所有预览和新的 `inspection-report.json` 均写入输出目录，不覆盖归档素材或历史报告。

默认仅对未修改的背景做窗口截取和显示尺寸缩放，不插入角色、不调用游戏输入。需要仅核对资源能否正常解码时，使用下列单张原尺寸输出；它不裁切或缩放，也不重新编码生产 WebP：

```sh
node docs/art/library-v26/inspect-crops.mjs --native-only --output /tmp/library-v26-native-inspection
```

原准备阶段还检查了原图副本与工具输出逐字节一致、WebP 解码尺寸与 RGB 模式不变。原记录中 WebP 相对原图各 RGB 通道平均绝对误差约 1.847/1.458/2.086（0–255），符合本次有损编码属性；不能将 WebP 称为逐像素无损副本。本次归档只复核路径、文件内容与解析，并执行一次原尺寸解码输出，不重复上述裁切或误差测量。
